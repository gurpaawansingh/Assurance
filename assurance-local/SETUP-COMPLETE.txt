🚀 HOW TO USE:

STEP 1: Configure Email Credentials
────────────────────────────────────
Create a file: assurance-local/.env

EMAIL_USER=your-email@gmail.com
EMAIL_PASS=your-app-password

For Gmail:
1. Enable 2-Factor Authentication
2. Visit: https://myaccount.google.com/apppasswords
3. Generate app password for "Assurance Safety"
4. Copy 16-digit password to .env file

STEP 2: Run Both Servers (Keep Both Running)
─────────────────────────────────────────────
Terminal 1 - Frontend:
  cd assurance-local
  npm start
  → http://127.0.0.1:4173

Terminal 2 - Email Server:
  cd assurance-local
  npm run email-server
  → http://127.0.0.1:3001

STEP 3: Set Up Emergency System
────────────────────────────────
1. Open http://127.0.0.1:4173
2. Go to "Privacy & data" section
3. Configure two 4-digit PINs:
   • Safe PIN: Stops emergency
   • Alert PIN: Triggers silent alert
4. Go to "Trusted people" section
5. Add contacts WITH EMAIL ADDRESSES

STEP 4: Test Emergency Alerts
──────────────────────────────
Option A - Auto-Start Test:
  1. Refresh the page
  2. 60-second countdown starts
  3. Let it expire → emergency triggers
  4. Check email server logs
  5. Check recipient inboxes

Option B - Manual Test:
  1. Click "Emergency" button
  2. Allow location access
  3. Emails sent automatically
  4. Check server logs and inboxes

🔧 TROUBLESHOOTING:

❌ "Email server unavailable"
   → Check Terminal 2 is running npm run email-server
   → Verify http://127.0.0.1:3001/health returns status

❌ "Invalid login" error
   → Check .env file exists with correct credentials
   → For Gmail, use app password (NOT regular password)
   → Ensure no spaces in EMAIL_PASS

❌ Emails not arriving
   → Check spam/junk folders
   → Verify email addresses are correct
   → Check email-server terminal for errors
   → Test with your own email first

❌ Location not included
   → Allow location permission in browser
   → Wait a few seconds for GPS fix
   → Keep page open and active
